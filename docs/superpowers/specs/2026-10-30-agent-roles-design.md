# Agent roles: one config for models, efforts and providers

One Synara thread per feature. The main agent (Opus high, set by Synara) delegates to role subagents. The user commits; agents never do (AGENTS.md golden rule).

## Why

- Mix models/efforts per role instead of running everything on the thread model.
- Swap any role's model, effort or provider (Claude, Codex, Antigravity) in one place. Codex will be dropped later; that must be a config edit.
- Reuse in other repositories later, so the tool must stay separable.

## Goals

- One config file holds provider/model/effort for every role.
- Writing/executing roles are Claude-only; read-only roles may use any provider.
- Unavailable external provider falls back to a Claude model of the same cost tier.
- Tool lives in Stagistic now as a self-contained directory that can move to its own repository unchanged.

## Non-goals

- Worktrees, port from env, Synara hub (later).
- Changing Superpowers skills; roles only decide who runs which skill.
- Configuring the main thread model (Synara owns it).
- Gemini/opencode as providers in v1 (installed, not required; adapter shape must allow adding them).

## Anti-goals

- External provider ever writing to the repository.
- Fallback silently moving to a more expensive tier.
- Stagistic specifics (moon, PGlite, product rules) inside the tool.
- Two sources of truth for a role's model.

## Roles

| Role | Default | Kind | Purpose |
|---|---|---|---|
| scout | Claude Haiku, low | read | Codebase search; uses graphify when the repo has it. |
| implementer | Claude Sonnet, medium | write | The only writer. |
| verifier | Claude Haiku, low | execute | Runs checks only, background. |
| reviewer | Claude Opus, high | read | Plan/diff review. |
| researcher | Claude Sonnet, medium | read | Web research. |

`write` and `execute` roles are locked to provider `claude`. Verifier counts as execute: check runners write caches/logs, which external read-only sandboxes block.

Read roles return a short result with `file:line` references or URLs.

## Layout

```
tools/agent-roles/            # self-contained; no imports from the repo
  README.md
  roles.default.json          # tool defaults: roles, tiers
  prompts/<role>.md           # generic role prompts
  bin/ask.mjs                 # external provider wrapper
  bin/sync.mjs                # generates .claude/agents/*.md
  lib/…                       # config merge, validation, adapters
  skills/external-agents/SKILL.md
.agents/roles.json            # Stagistic override (optional, partial)
.claude/agents/<role>.md      # generated, committed, header "generated by agent-roles sync"
```

Config layers, later wins: `roles.default.json` → `.agents/roles.json` (repo, optional). Merge is per role, per field. (A user layer `~/.config/agent-roles/roles.json` was dropped after review: generated agent files are committed, so a per-machine layer made `sync --check` fail for everyone else.)

Repository specifics stay in the repo's `AGENTS.md` (verification commands, delegation triggers, golden rules). Role prompts say "follow the repository's AGENTS.md/CLAUDE.md" and contain nothing repo-specific.

Stagistic wiring is limited to: `.agents/roles.json`, a `root:agents-sync` moon task, the "Delegation" section in `AGENTS.md`, and the skill being discoverable (symlink or copy into `.claude/skills/`; builder's call, must survive extraction).

## Config shape

```json
{
  "roles": {
    "reviewer": { "provider": "codex", "model": "<id>", "effort": "high" }
  },
  "tiers": {
    "claude": { "haiku": "low", "sonnet": "mid", "opus": "high" },
    "codex":  { "<id>": "mid", "<id>": "high" },
    "agy":    { "<id>": "high" }
  },
  "efforts": {
    "claude": ["low", "medium", "high", "xhigh", "max"],
    "codex":  ["low", "medium", "high", "xhigh", "max", "ultra"],
    "agy":    ["low", "medium", "high", "xhigh", "max"]
  },
  "effortToClaude": {
    "codex": { "ultra": "max", "…": "…" },
    "agy":   { "high": "high", "…": "…" }
  },
  "timeoutSeconds": 600
}
```

- `effort` is written in the provider's own vocabulary. codex receives it (`model_reasoning_effort`); agy does not (its model ids carry the effort and it rejects `--effort`), so for agy it only selects the Claude fallback effort.
- `efforts.<provider>` lists valid values (replaced per layer); `effortToClaude.<provider>` maps an external effort to the fallback's Claude effort (merged per key).
- `kind` and `tools` per role are fixed by the tool defaults; overrides may set only `provider`, `model`, `effort`.
- Exact model ids, effort values and tier assignments: see Spike findings.

## sync

- Merges config, validates, writes one `.claude/agents/<role>.md` per role from `prompts/<role>.md`.
- Every role always gets a full Claude agent file. Claude provider: frontmatter sets the configured `model`/effort. External provider: frontmatter sets the tier-matched Claude fallback model/effort (see Fallback), and the file is marked `external: <provider>/<model>`.
- Tool allow-list per kind (read roles: no Write/Edit; verifier: Bash + Read). Best-effort enforcement via allow-list + prompt; external providers get hard read-only from their own sandbox. No hook in v1 (my call).
- Validation at sync time fails with a clear message when: a write/execute role has a non-Claude provider; provider unknown; model missing from that provider's tier table; effort invalid for the provider; the Claude tier table lacks a model for a tier used by an external role.
- `--check` mode reports drift between config and generated files without writing (usable in lint/hooks).

## ask.mjs

- `ask.mjs --role <role> [--cwd <dir>] <prompt|-->` resolves provider/model/effort from the merged config. `--provider/--model/--effort` override for one call.
- Adapters, always read-only:
  - codex: `codex exec --skip-git-repo-check -s read-only -m <model> -c model_reasoning_effort="<e>" -c web_search="live" -C <cwd> -o <file> -`, prompt on stdin, answer read from `<file>`.
  - agy: `agy --print=<prompt> --sandbox --model <m> --output-format json` (default headless mode, which auto-denies writes; not `--mode plan`, which writes a plan instead of answering; no `--effort`). Answer from JSON `.response`.
- Prints only the final answer. Exit codes: `0` success, `1` task failure/timeout, `2` usage/config error, `3` provider unavailable. The exit-3 message names the cause, the fix (e.g. "run `codex login`") and the fallback subagent's model: the stored config's fallback, also when `--provider/--model/--effort` overrode the call, because the fallback subagent runs from the generated agent file.
- "Provider unavailable" is detected from CLI output text, not exit codes (both CLIs exit 1 for everything):
  - not installed: spawn fails with `ENOENT`;
  - not logged in / quota: error text matches `not logged in|authenticat|unauthori[sz]ed|401|login required` or `quota|rate limit|429|usage limit`. For codex only stderr lines starting with `ERROR:` count (its stderr also echoes the prompt); for agy the JSON `.error` field, else stderr;
  - agy waiting for interactive authentication ("Waiting for authentication" on stderr) is killed immediately.
- Exit code 0 is not trusted alone: codex without a non-empty answer file, or agy with `status` ≠ `SUCCESS` or an empty `.response` (e.g. `denied_actions`), is a task failure (or unavailable when the error text matches).
- Timeout per call; configurable.

## Dispatch and fallback (my call: no dispatcher subagent)

A subagent cannot change its own model, so the main agent does dispatch, guided by the `external-agents` skill:

1. Role provider `claude` → spawn subagent `<role>`.
2. Role provider external → run `ask.mjs --role <role> "<prompt>"` via Bash (background when long).
3. `ask.mjs` exits with the "unavailable" code → spawn subagent `<role>` (already on the tier-matched Claude model) and tell the user: "served by Claude Sonnet instead of codex/<id>: not logged in".

Rules:
- Tier table holds exactly one Claude model per tier (low/mid/high); sync enforces it, so fallback is deterministic and resolved at sync time.
- Effort mapping: config holds a per-provider map to Claude effort levels (e.g. codex `xhigh` → Claude `high`); sync applies it.
- No tier match is a sync error, never a runtime upgrade.
- Task failures (bad answer, timeout after start) do not fall back; they are reported.

## Delegation section in AGENTS.md

Concrete triggers:
- Search across more than 3 files → scout.
- Plan with ≥2 tasks → implementer.
- Full suites → verifier, background.
- UI changes → visual check in the main thread.
- Second opinion on plan/diff → reviewer.

Rules:
- One writer.
- Tests only at checkpoints, per the existing "Agent verification workflow".
- At most one browser suite and one moon run at a time.
- Approval points: design, plan, final review before commit.

## Spike findings (2026-10-30)

- Claude Code subagent frontmatter supports `model` (aliases `haiku|sonnet|opus|fable` or full id) and `effort` (`low|medium|high|xhigh|max`). Agent tool can also pass `model`/`effort` per call.
- Synara loads `.claude/agents/` only at session start; a file added mid-session is not spawnable. Pilot must run in a new thread.
- codex 0.166: `codex exec -s read-only -m <id> -c model_reasoning_effort="<e>" -C <dir> -o <file> -` (prompt on stdin). Models (`~/.codex/models_cache.json`): `gpt-6.1-sol`, `gpt-6-sol`, `gpt-6-astra`, `gpt-6.1-terra`, `gpt-6-luna`, `gpt-5.6-*`. Efforts `low|medium|high|xhigh|max|ultra`. Logged out: exit 1, stderr `401 Unauthorized` after 5 reconnects. Web search works with `-c web_search="live"`. Outside a git repo needs `--skip-git-repo-check`.
- agy: `--mode plan` writes an implementation plan instead of answering → unusable. Default headless mode auto-denies writes (`denied_actions: write_file`); use it with `--sandbox`. Answer in JSON `.response`; failures `status: "ERROR"` + `.error`. Logged out: blocks on "Waiting for authentication" until `--print-timeout` → detect on stderr and kill. Models: `gemini-3.8-flash-{low,medium,high}`, `claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`. Efforts `low|medium|high|xhigh|max`.
